# Kubernetes (k8s) Notes

## Overview

- Platform used to orchestrate deployment, scaling, and management of container-based applications.

Common tasks:

- Balancing load between nodes
- Managing updates
- Mounting storage systems
- Accessing app logs
- Distributing secrets
- Debugging applications
- Monitoring resources

---

## How a Container Runs in a Cluster

### Control Plane

- Responsible for managing the state of the cluster
- Runs on multiple nodes/zones

#### API Server

- Primary interface between the control plane and the rest of the cluster
- Exposes a REST API that allows clients to interact with the control plane and submit requests to manage the cluster

#### etcd

- Distributed key-value store
- Stores the cluster's persistent state
- Used by other components to store and retrieve info on the cluster

#### Scheduler

- Responsible for scheduling pods onto the worker nodes
- Uses info about the resources required by the pods and the available resources on the worker nodes to make placement decisions

#### Controller Manager

- Responsible for running controllers that manage the state of the cluster
- e.g. replication, deployment

---

### Worker Nodes

#### Kubelet

- Node agent that runs on each worker node
- Responsible for communicating with the control plane
- Receives instructions and ensures the desired state is maintained

#### Container Runtime

- Runs the containers
- Responsible for pulling container images from a registry, starting and stopping a container, and managing container resources

#### Kube-Proxy

- Routes traffic to the correct pods
- Also does load balancing

### QOS

when a pod gets squezed for resources (memory,cpu) k8s  uses QOS to decide what pods will get evicted 

-  Guaranteed: Every container in the pod has requests equal to limits no more, no less. These pods get evicted last.
-  Burstable : atlease one container has has a request lower then its limit These pods get evicted seconf 
-  Best effort: this has no limits and gets evivted first when pressire hits.

### rolling updates

- max unavlable: max nunber of pods that can be down at one point (ensures that most of the capacity is serving traffic)
